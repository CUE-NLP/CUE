# CUE Frontend 작업 가이드

## 현재 화면 구조

- 스타일링은 Tailwind CSS v4와 `@tailwindcss/vite`를 사용한다. 기존 화면의 Tailwind 유틸리티 매핑은 `src/tailwindStyles.ts`의 `tw()`에 있으며, 새 UI는 JSX 유틸리티 클래스로 작성한다. `src/styles.css`는 Tailwind import와 전역 폰트·포커스·키프레임만 둔다. Prettier 형식 검사는 `npm run format:check`, 빌드 검사는 `npm run build`로 확인한다.

- `src/App.tsx`: 화면 전환·사용자·선택 아이디어 공유 상태. URL 라우터 없이 앱 내부 페이지 상태를 사용한다.
- `src/pages/`: 시작, 로그인·회원가입, 키보드·음성 입력, 구조화 확인, 리더보드, 저장 결과, 평가 상세 화면.
- `src/components/`: 버튼·하단 메뉴·오류 배너 및 가중치 설정, 구조화 수정, 근거 문서, 변화 알림, 포트폴리오 카드 모달.
- `src/api/`: 인증, 아이디어, 평가, 이력, 가중치 예약, 수정 및 변화 확인 요청과 타입. 점수와 근거는 실제 API 데이터로만 표시한다.
- 입력 화면의 구조화 버튼은 `POST /api/ideas/structure`로 원문을 바탕으로 추천 제목(최대 60자)과 네 항목을 확인 화면에 채운다. 가중치는 TREND 포함 다섯 개의 합계가 100일 때 다음 평가에 적용하도록 예약한다.

- React 19 + TypeScript + Vite. `src/App.tsx`는 화면 흐름, `src/api/`는 백엔드 요청과 타입, `src/styles.css`는 Figma 기반 반응형 스타일이다.
- 개발 서버는 5173 포트를 사용하고 `/api`를 `localhost:8080`으로 프록시한다. `npm install`, `npm run dev`, `npm run build`로 실행과 검증을 한다.
- 백엔드의 응답은 `CommonResponse<T>`이며 `data`를 읽는다. 보호된 API에는 JWT를 붙인다. `A004` 때 refresh 토큰을 한 번 교체하고 요청을 재시도한다.
- 음성 받아쓰기는 브라우저에서 처리하고 녹음 파일은 전송하거나 저장하지 않는다. 구조화 버튼을 누르면 원문 텍스트만 `POST /api/ideas/structure`로 보낸다(서버는 저장하지 않음). 네 항목 중 비어 있는 항목은 안내 문구로 알려 준다. 사용자가 확인·수정한 제목과 네 항목은 `POST /api/ideas`로 저장한다. 제목이 비어 있으면 요청에서 생략한다. `keywords`는 보내지 않는다(보내면 출처가 USER가 된다).
- 같은 원문으로 다시 누르면 API를 부르지 않고 이전 결과와 사용자가 고친 내용을 그대로 쓴다(제미나이 호출 절약). 구조화가 실패하면(`I006`, `E006`, `E001`, `E002`, `G002` 등) 원문을 문제 칸에 넣고 확인 화면으로 넘어가며, 오류 배너로 직접 채우도록 안내한다.
- `IDLE`은 완료를 의미하지 않는다. `lastEvaluatedAt`이 없으면 미평가로 표시하고, 평가 요청 버튼은 `POST /api/ideas/{id}/evaluate`를 호출한다. 진행 중에는 상세 API를 주기적으로 조회한다. 평가는 아이디어마다 하루 한 번이라 오늘 이미 평가한 아이디어에 다시 요청하면 `E007`(409)이다(내용·키워드를 수정했거나 실패한 경우는 가능).

## 평가 흐름 (팀 결정)

- 백엔드는 `EVALUATION_AUTO_ON_SAVE=false`로 실행한다(시연 포함). 서버는 저장·수정만으로 평가를 시작하지 않는다. 대신 확인 화면의 "확인하고 평가하기"는 저장 결과가 `ACTIVE`(네 칸이 모두 참)면 바로 `POST /api/ideas/{id}/evaluate`를 보내 평가 중 화면을 띄운다. 빈 칸이 있으면 `HOLD`로 저장되고 평가를 요청하지 않는다. 수정한 내용은 다음 평가(새벽 3시 일일 배치 등)에 반영된다.
- 평가 요청 버튼은 저장 결과 화면에만 둔다. 저장 직후 평가 요청이 실패했거나 아직 평가되지 않았을 때("평가 요청하기")와 `FAILED`일 때("다시 평가 요청하기")만 보인다. 저장 직후 평가 요청이 실패하면 "저장은 됐지만 평가를 요청하지 못했어요" 배너를 띄운다. 일일 재평가가 있으므로 상세 화면에는 다시 평가·새로고침 버튼을 두지 않는다.
- `QUEUED`·`RUNNING` 동안 저장 결과·상세 화면은 3초마다 `GET /api/ideas/{id}`를 조회한다. 저장 결과 화면은 이 동안 "아이디어의 가능성을 살펴보고 있어요" 로딩 화면을 보여 준다.
- 보류로 저장했거나 평가 요청이 실패하면 저장(`POST /api/ideas`) 응답 대신 `GET /api/ideas/{id}`로 한 번 더 받아 최신 상태를 보여 준다.

## 화면별 표시 규칙

- **상세 화면**: 평가 결과·근거 자료·이력 세 탭이다.
  - 평가 결과: 첫 평가면 "첫 평가 결과"로 지표별 점수와 판단 근거(`evidenceSummary`)를, 재평가면 "무엇이 달라졌나요?"로 바뀐 지표만 ▲(초록)/▼(빨강)과 이전 평가 점수를 보여 준다. 나머지는 "나머지 N개 지표는 유지됐어요. 보기 ▾"로 접어 두고, 누르면 지표마다 현재 점수(예: "문제 중요성 50", 화살표 없음)와 그 지표가 마지막으로 바뀐 평가의 판단 근거를 펼친다(이번 회차에 바뀌지 않은 지표는 새 근거가 저장되지 않는다).
  - 근거 자료: `GET /api/ideas/{id}/evaluations`의 `references`를 문서 카드로 보여 준다. 카드에는 지표 변화와 종합 점수 기여(`difference × weightPercent`, "· 종합 ±M점")를 적고, 누르면 근거 문서 모달에서 판단 근거와 계산식을 보여 준다. 문서가 없으면 "연결된 근거 문서가 없어요."를 표시한다.
  - 이력: `GET /api/ideas/{id}/history`를 SVG 꺾은선 그래프로 직접 그린다(차트 라이브러리 없음).
- **리더보드**: 1~3위 메달과 순위 원, 가장 크게 바뀐 지표 칩(▲/▼, "변화 없음"), 상태 배지, 총점 스파크라인, "최근 상승 N개", 보류 카드 안내를 보여 준다. 목록 API에 점수 이력이 없어 스파크라인은 평가된 아이디어마다 `history`를 한 번 부르고 `lastEvaluatedAt`으로 캐시한다. `scores[].latestDifference`는 그 지표가 마지막으로 바뀐 평가의 값이므로 첫 평가 값은 칩에 쓰지 않는다.
- **변화 알림 모달**: 확인하지 않은 변화(`hasNewChange`)만 상승 초록 ▲, 하락 빨강 ▼, 첫 평가 완료, 변화 없음으로 보여 주고, 누르면 `POST /api/ideas/{id}/check` 후 상세로 이동한다.
- **구조화 수정 모달**: 평가 중(`QUEUED`·`RUNNING`)에는 수정할 수 없고 `I005`도 같은 안내로 처리한다. 제목만 바꾸면 `PATCH /api/ideas/{id}`에 `title`만 보내며 평가를 예약하지 않는다. 제목 칸 밑에 "제목은 점수에 영향이 없어요."를, 저장 버튼 위에 "수정한 내용은 다음 자동 평가 때 반영돼요."를 항상 보여 준다. 네 항목 중 빈칸이 있으면 그 자리에 보류 경고를, 평가 중이면 수정 불가 안내를 대신 보여 준다.
- **카드 요약 모달**: 손잡이·닫기(×) 없는 가운데 카드로, 굵은 제목·총점·한 줄 소개·닫기 버튼만 보여 준다. 요약 API가 없어 한 줄 소개는 AI 없이 "{타깃}을/를 위한 {제목}이에요/예요."로 만들고(받침으로 조사 선택), 타깃이나 저장된 제목이 없으면 해결 방법(없으면 문제)을 자르지 않고 보여 준다. 상세 화면에서 여는 모달 제목(구조화 수정, 평가 가중치 설정, 카드 요약)은 굵게 쓴다.
- **아이디어 제목**: 목록·상세·결과·모달은 `ideaTitle()`로 저장된 제목을 표시한다. 제목이 없는 아이디어는 해결 또는 문제의 앞부분을 최대 60자로 보여 준다.
- **입력 화면**: 입력이 비어 있거나 공백뿐이면 구조화 버튼을 누를 수 없다. 아이콘은 SVG로 직접 그린다.
- 새 라이브러리 없이 구현한다. 그래프·아이콘은 SVG로 그린다.
- 화면/API/구조가 바뀌면 이 문서와 루트 `README.md`의 Frontend 안내도 함께 갱신한다. 커밋, 푸시, PR은 사용자가 요청할 때만 진행한다.
