# CUE Frontend 작업 가이드

- `MyIdeasPage`는 리더보드와 분리된 개인 아이디어 보관함이다. ACTIVE와 HOLD를 함께 불러와 기본 최근 기록순으로 표시하고, 점수순·보류로 전환할 수 있다. 각 필터에는 해당 건수를 선명한 숫자 배지로 표시하고 목록·캐러셀 카드 왼쪽에는 현재 정렬 순서의 `1, 2, 3…` 숫자를 회색 원 안에 표시한다. 기본 보기는 세로 카드 목록이며 아이콘 토글로 3D 회전 캐러셀로 전환한다. 목록 카드는 제목·기록 시각·요약과 오른쪽 상태 원을 표시한다(평가 완료 초록, 보류 노랑, 기타 상태 중립/오류색). 캐러셀의 SVG 화살표는 원 중앙에 배치한다. 양옆 카드, 이전·다음 버튼, 좌우 스와이프, 방향키로 순환하고 중앙 카드를 누르면 상세로 이동한다. 상세에서 뒤로 가면 진입한 리더보드 또는 내 아이디어 탭으로 돌아간다.

- 홈 입력의 음성 모드는 브라우저 받아쓰기와 마이크 입력 진폭 분석을 함께 사용한다. 녹음 중 빨간 중지 버튼과 말소리에 반응하는 파형을 표시하고, 입력 방식 전환에는 짧은 전환 효과를 사용한다. 구조화 버튼은 "구조화하기"로 표시한다.
- 리더보드의 "점수순"은 종합 점수 내림차순, "최근 상승"은 직전 평가 대비 점수 상승폭(`lastDifference`) 내림차순이다. 평가 설정 선택 시트는 ACTIVE 아이디어를 복수 선택하고 같은 가중치를 각각의 기존 API로 예약한다. 일부 요청이 실패하면 실패한 아이디어만 다시 저장할 수 있게 둔다.
- 상세 화면의 개별 재평가는 `POST /api/ideas/{id}/evaluate`를 사용한다. 하루에 이미 평가했으면 E007이고, 보류 아이디어는 요청하지 않는다. 카드 요약에는 최초 작성 시각을 표시한다. 근거 문서 응답에는 개별 수집 시각이 없으므로 해당 문서가 평가에 반영된 시각(`evaluatedAt`)이라고 명확하게 표시한다.

- 홈 탭은 아이디어 기록 화면이다. 기존 `InputPage`의 키보드·음성 입력과 구조화 확인 흐름을 홈에서 바로 사용할 수 있고, 하단 탭으로 리더보드·내 아이디어·설정에 이동한다. 리더보드는 순위 목록, 내 아이디어는 회전 캐러셀로 구분한다.
- 설정 탭은 독립된 내 정보 화면이며 `GET /api/users/me`의 닉네임·이메일, 서버 고정 24시간 재평가 주기를 보여 준다. 평가 주기 변경 버튼과 회원 카드 우측 상단 연필 버튼은 각각 준비 중 모달을 연다. Basic 요금제 표시는 시연용 목업이며 서버 계정 데이터와 연결되지 않는다. 로그아웃 버튼은 중앙 확인 모달을 거쳐 기존 API를 호출한다.

- 평가 설정 선택 시트는 내용 높이만 차지하고 목록이 많아질 때 내부만 스크롤한다. 평가 설정 버튼은 hover·포커스에 강조를 준다. 카드 점수 영역은 오른쪽 고정 폭에 배치하고 긴 제목은 줄바꿈한다. 상세 제목도 생략 부호 없이 줄바꿈한다.
- 보류 카드에는 작성 시각과 저장된 구조화 내용 미리보기를 표시한다. 입력 원문은 백엔드에 저장되지 않으므로 상세에 그 사실을 안내한다. 네 구조화 항목 중 하나라도 비면 HOLD가 되고 평가하지 않는다.

- 리더보드 목록은 세로 스크롤 카드와 위치를 알려 주는 우측 점 내비게이션을 쓴다. 점을 누르면 해당 카드로 이동하고 스크롤해도 활성 점이 갱신된다. 카드 목록의 기본 스크롤바는 숨기되 휠·터치·키보드 스크롤은 유지한다. 필터·카드·새 아이디어 버튼은 hover와 키보드 포커스에서 강조하며, 스파크라인은 이력 선 아래를 채운다. 평가 설정 아이디어 선택은 점수 배지와 제목을 담은 카드형이며 목록 내부에서만 스크롤한다.
- 수동 평가 버튼은 "지금 재평가"로 표기하고, 24시간마다 근거 자료 변화를 수집해 재평가한다는 설명을 표시한다. 호출은 기존 `POST /api/demo/evaluations/run`이다.

- 구조화 확인 화면의 원문 제목은 "내가 적은 아이디어 원문"이다. "이렇게 이해했어요" 제목과 "의도와 다르면 수정해 주세요." 문구는 표시하지 않는다. 네 항목 카드의 연필은 우측 상단에 배치하고 본문은 연필 아래까지 폭을 사용한다. 본문 입력칸은 사용자가 크기를 직접 조절하는 손잡이를 표시하지 않는다.

- CUE 로고가 있는 모든 화면은 카드 안의 상단 여백을 30px(낮은 화면에서는 24px)로 맞춘다. 데스크톱에서는 화면별 카드의 바깥쪽 상단 위치도 통일한다. 공통 `Brand`의 뒤로가기 버튼과 로고 간격은 4px이며, 시작 화면의 일러스트 배치는 별도로 유지한다.

## 03 상세 화면 QA 반영

- 카드 요약은 카드 가운데에서 일정 높이로 유지하고 구조화 항목 영역만 스크롤한다. 앱의 모든 스크롤 표시는 4px 보라색 인디케이터를 공통으로 쓴다. 상세 카드 안쪽의 브랜드 위 여백은 30px로 줄인다.
- 최고 가중치 문구는 사용하지 않고 각 지표에 `가중치 N%`만 주황색으로 표기한다. 총점 기여 막대는 밝은 주황색, 이전 평가 점수는 총점 아래 오른쪽에 표시한다.

- 상세 화면의 세 동작 버튼은 가운데 정렬하고 hover/키보드 포커스에 약한 상승 효과를 준다. 구조화 수정에서는 제목·타깃·문제·해결·기대효과만 외곽 카드로 구분하고 입력칸의 중첩 테두리는 두지 않는다.
- 상세 화면도 큰 화면에서 카드 위쪽 여백을 줄인다. 총점의 숫자와 '점', 점수 변동은 한 줄로 유지하고 이전 평가 점수나 첫 평가 날짜는 아래 줄에 표시한다. 총점 기여 막대는 주황색 계열이다.

- 각 지표의 원점수는 보라색, 현재 가중치를 반영한 총점 기여(`점수 × 가중치 / 100`)는 주황색 막대로 구분한다. 지표별 가중치는 원점수 숫자 왼쪽에 표시하며 점수의 우열을 뜻하지 않는다.
- 근거 카드 hover/포커스는 내용 뒤쪽의 약한 보라색 그림자를 사용한다. 스크롤 가능한 카드에는 얇은 보라색 표시를 사용한다. 홈·리더보드·내 아이디어 화면의 큰 화면 상단 여백은 절반 수준으로 줄인다.

- 평가 결과 탭에서는 평가 지표 카드를 먼저 보여주고, AI가 반환한 `evidenceSummary`는 원문을 유지한 채 기본 3줄로 접어 둔다. 각 평가이유의 버튼으로 전체 내용을 펼칠 수 있다.
- 근거 자료 카드의 점수 정보는 왼쪽으로 정렬한다. 이력 카드는 `yy.MM.dd HH:mm`, 공통 날짜는 `yy.MM.dd` 형식을 사용한다.
- 평가 가중치 시트는 퍼센트 양옆에 1% 감소·증가 버튼과 슬라이더를 함께 제공한다. 합계 카드가 100%일 때 성공 색과 안내 문구를 표시하며 저장 버튼을 활성화한다. 평가이유가 3줄을 넘으면 오른쪽에 "더보기" 버튼을 표시한다.
- 평가 지표의 보라색 막대는 원점수/100, 그 아래 얇은 주황색 막대는 `원점수 × 현재 가중치 / 100`이 전체 100점에 기여한 몫이다. 총점 구성 막대는 두지 않는다. 카드 요약에는 점수별 표 대신 구조화한 타깃·문제·해결·기대효과를 표시한다. 예약 가중치는 다음 평가 전까지 표시값에 섞지 않는다.
- 연결된 근거 문서와 근거 자료 카드는 `styles.css`의 카드 전용 광원 효과로 호버·키보드 포커스·터치에 반응한다. 문서 모달의 원문 보기, 근거 자료 카드의 상세 보기, 이력의 근거 문서 보기와 평가이유 더보기 문구는 오른쪽 정렬한다. 상세 탭의 활성 상태는 보라색 밑줄로 표시한다.
- 구조화 수정 시트는 보라색 소제목과 연보라색 카드 필드로 표시한다.

## 현재 화면 구조

- 스타일링은 Tailwind CSS v4와 `@tailwindcss/vite`를 사용한다. 기존 화면의 Tailwind 유틸리티 매핑은 `src/tailwindStyles.ts`의 `tw()`에 있으며, 새 UI는 JSX 유틸리티 클래스로 작성한다. `src/styles.css`에는 Tailwind import와 전역 폰트·포커스·키프레임, 근거 카드 광원 상태 스타일을 둔다. Prettier 형식 검사는 `npm run format:check`, 빌드 검사는 `npm run build`로 확인한다.

- `src/App.tsx`: 화면 전환·사용자·선택 아이디어 공유 상태. URL 라우터 없이 앱 내부 페이지 상태를 사용한다.
- `src/pages/`: 시작, 로그인·회원가입, 키보드·음성 입력, 구조화 확인, 리더보드, 저장 결과, 평가 상세 화면.
- `src/components/`: 버튼·하단 메뉴·오류 배너 및 가중치 설정, 구조화 수정, 근거 문서, 변화 알림, 포트폴리오 카드 모달.
- `src/api/`: 인증, 아이디어, 평가, 이력, 가중치 예약, 수정 및 변화 확인 요청과 타입. 점수와 근거는 실제 API 데이터로만 표시한다.
- 입력 화면의 구조화 버튼은 `POST /api/ideas/structure`로 원문을 바탕으로 추천 제목(최대 60자)과 네 항목을 확인 화면에 채운다. 가중치는 TREND 포함 다섯 개의 합계가 100일 때 다음 평가에 적용하도록 예약한다.

- React 19 + TypeScript + Vite. `src/App.tsx`는 화면 흐름, `src/api/`는 백엔드 요청과 타입, `src/styles.css`는 Figma 기반 반응형 스타일이다.
- 개발 서버는 5173 포트를 사용하고 `/api`를 `localhost:8080`으로 프록시한다. `npm install`, `npm run dev`, `npm run build`로 실행과 검증을 한다.
- 백엔드의 응답은 `CommonResponse<T>`이며 `data`를 읽는다. 보호된 API에는 JWT를 붙인다. `A004` 때 refresh 토큰을 한 번 교체하고 요청을 재시도한다.
- 음성 받아쓰기는 브라우저에서 처리하고 녹음 파일은 전송하거나 저장하지 않는다. 구조화 버튼을 누르면 원문 텍스트만 `POST /api/ideas/structure`로 보낸다(서버는 저장하지 않음). 네 항목 중 비어 있는 항목은 안내 문구로 알려 준다. 사용자가 확인·수정한 제목과 네 항목은 `POST /api/ideas`로 저장한다. 제목이 비어 있으면 요청에서 생략한다. `keywords`는 보내지 않는다(보내면 출처가 USER가 된다).
- 같은 원문으로 다시 누르면 API를 부르지 않고 이전 결과와 사용자가 고친 내용을 그대로 쓴다(제미나이 호출 절약). 구조화가 실패하면(`I006`, `E006`, `E001`, `E002`, `G002` 등) 원문을 문제 칸에 넣고 확인 화면으로 넘어가며, 오류 배너로 직접 채우도록 안내한다.
- `IDLE`은 완료를 의미하지 않는다. `lastEvaluatedAt`이 없으면 미평가로 표시하고, 평가 요청 버튼은 `POST /api/ideas/{id}/evaluate`를 호출한다. 진행 중에는 상세 API를 주기적으로 조회한다. 평가는 아이디어마다 하루 한 번이라 오늘 이미 평가한 아이디어에 다시 요청하면 `E007`(409)이다(내용·키워드를 수정했거나 실패한 경우는 가능). 평가 실패는 `lastEvaluationError`(`location`·`api`·`reason`)로, 외부 AI 호출이 실패한 응답은 `data`의 같은 필드로 원인을 알 수 있다(아직 화면에는 표시하지 않는다).

## 평가 흐름 (팀 결정)

- 백엔드는 `EVALUATION_AUTO_ON_SAVE=false`로 실행한다(시연 포함). 서버는 저장·수정만으로 평가를 시작하지 않는다. 대신 확인 화면의 "확인하고 평가하기"는 저장 결과가 `ACTIVE`(네 칸이 모두 참)면 바로 `POST /api/ideas/{id}/evaluate`를 보내 평가 중 화면을 띄운다. 빈 칸이 있으면 `HOLD`로 저장되고 평가를 요청하지 않는다. 수정한 내용은 다음 평가(새벽 3시 일일 배치 등)에 반영된다.
- 리더보드 "24시간마다 자동 확인" 줄 오른쪽의 "↻ 지금 확인" 버튼은 시연·수동 평가용으로 `POST /api/demo/evaluations/run`(`force` 없이)을 보내 내 ACTIVE 아이디어 전부를 지금 확인·평가한다. 서버가 늘 켜져 있지 않아 정해진 시각의 자동 평가를 놓칠 수 있으므로, 이 버튼으로 날마다 데이터를 쌓는다. 누르면 "확인하는 중…"으로 바뀌고 큐에 들어간(이미 평가 중인 것 포함) 아이디어가 끝날 때까지 3초마다 목록을 다시 받은 뒤 "확인을 마쳤어요."(실패가 있으면 개수)를 보여 준다. `D002`는 30초 뒤 다시 누르라는 안내, `D001`은 버튼을 숨기고 꺼져 있다는 안내, 그 밖의 오류는 오류 배너로 처리한다.
- 평가 요청 버튼은 저장 결과 화면에만 둔다. 저장 직후 평가 요청이 실패했거나 아직 평가되지 않았을 때("평가 요청하기")와 `FAILED`일 때("다시 평가 요청하기")만 보인다. 저장 직후 평가 요청이 실패하면 "저장은 됐지만 평가를 요청하지 못했어요" 배너를 띄운다. 일일 재평가가 있으므로 상세 화면에는 다시 평가·새로고침 버튼을 두지 않는다.
- `QUEUED`·`RUNNING` 동안 저장 결과·상세 화면은 3초마다 `GET /api/ideas/{id}`를 조회한다. 저장 결과 화면은 이 동안 "아이디어의 가능성을 살펴보고 있어요" 로딩 화면을 보여 준다.
- 보류로 저장했거나 평가 요청이 실패하면 저장(`POST /api/ideas`) 응답 대신 `GET /api/ideas/{id}`로 한 번 더 받아 최신 상태를 보여 준다.

## 화면별 표시 규칙

- **상세 화면**: 평가 결과·근거 자료·이력 세 탭이다.
  - 평가 결과: 첫 평가면 "첫 평가 결과"로 지표별 점수와 판단 근거(`evidenceSummary`)를, 재평가면 "무엇이 달라졌나요?"로 바뀐 지표만 ▲(초록)/▼(빨강)과 이전 평가 점수를 보여 준다. 나머지는 "나머지 N개 지표는 유지됐어요. 보기 ▾"로 접어 두고, 누르면 지표마다 현재 점수(예: "문제 중요성 50", 화살표 없음)와 그 지표가 마지막으로 바뀐 평가의 판단 근거를 펼친다(이번 회차에 바뀌지 않은 지표는 새 근거가 저장되지 않는다).
  - 근거 자료: `GET /api/ideas/{id}/evaluations`의 `references`를 문서 카드로 보여 준다. 카드에는 지표 변화와 종합 점수 기여(`difference × weightPercent`, "· 종합 ±M점")를 적고, 누르면 근거 문서 모달에서 판단 근거와 계산식을 보여 준다. 문서가 없으면 "연결된 근거 문서가 없어요."를 표시한다.
  - 이력: `GET /api/ideas/{id}/history`를 SVG 꺾은선 그래프로 직접 그린다(차트 라이브러리 없음).
- **리더보드**: "↻ 지금 확인" 버튼(위 "평가 흐름"), 1~3위 메달과 순위 원, 가장 크게 바뀐 지표 칩(▲/▼, "변화 없음"), 상태 배지, 총점 스파크라인, "최근 상승 N개", 보류 카드 안내를 보여 준다. 목록 API에 점수 이력이 없어 스파크라인은 평가된 아이디어마다 `history`를 한 번 부르고 `lastEvaluatedAt`으로 캐시한다. `scores[].latestDifference`는 그 지표가 마지막으로 바뀐 평가의 값이므로 첫 평가 값은 칩에 쓰지 않는다.
- **변화 알림 모달**: 확인하지 않은 변화(`hasNewChange`)만 상승 초록 ▲, 하락 빨강 ▼, 첫 평가 완료, 변화 없음으로 보여 주고, 누르면 `POST /api/ideas/{id}/check` 후 상세로 이동한다.
- **구조화 수정 모달**: 평가 중(`QUEUED`·`RUNNING`)에는 수정할 수 없고 `I005`도 같은 안내로 처리한다. 제목만 바꾸면 `PATCH /api/ideas/{id}`에 `title`만 보내며 평가를 예약하지 않는다. 제목 칸 밑에 "제목은 점수에 영향이 없어요."를, 저장 버튼 위에 "수정한 내용은 다음 자동 평가 때 반영돼요."를 항상 보여 준다. 네 항목 중 빈칸이 있으면 그 자리에 보류 경고를, 평가 중이면 수정 불가 안내를 대신 보여 준다.
- **카드 요약 모달**: 손잡이·닫기(×) 없는 가운데 카드로, 굵은 제목·총점·한 줄 소개·닫기 버튼만 보여 준다. 요약 API가 없어 한 줄 소개는 AI 없이 "{타깃}을/를 위한 {제목}이에요/예요."로 만들고(받침으로 조사 선택), 타깃이나 저장된 제목이 없으면 해결 방법(없으면 문제)을 자르지 않고 보여 준다. 상세 화면에서 여는 모달 제목(구조화 수정, 평가 가중치 설정, 카드 요약)은 굵게 쓴다.
- **아이디어 제목**: 목록·상세·결과·모달은 `ideaTitle()`로 저장된 제목을 표시한다. 제목이 없는 아이디어는 해결 또는 문제의 앞부분을 최대 60자로 보여 준다.
- **입력 화면**: 입력이 비어 있거나 공백뿐이면 구조화 버튼을 누를 수 없다. 아이콘은 SVG로 직접 그린다.
- 새 라이브러리 없이 구현한다. 그래프·아이콘은 SVG로 그린다.
- 화면/API/구조가 바뀌면 이 문서와 루트 `README.md`의 Frontend 안내도 함께 갱신한다. 커밋, 푸시, PR은 사용자가 요청할 때만 진행한다.
