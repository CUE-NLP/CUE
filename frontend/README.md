# CUE Frontend

내 아이디어 탭은 별도의 보관함 화면입니다. ACTIVE·HOLD 아이디어를 기본 최근 기록순으로 모아 보여주며 점수순·보류 필터로 전환할 수 있습니다. 전체 건수는 필터 버튼의 대비 높은 배지에만 표시하고, 카드 왼쪽에는 현재 목록에서 몇 번째인지 회색 원에 `1, 2, 3…`으로 표시합니다. 기본 세로 목록과 회전 캐러셀은 아이콘 버튼으로 전환합니다. 목록 카드는 제목·기록일·요약 및 오른쪽 상태 원을 보여줍니다(평가 완료 초록, 보류 노랑). 캐러셀의 가운데 정렬된 화살표나 양옆 카드, 좌우 스와이프로 이동합니다. 상세의 뒤로 가기는 진입한 탭으로 돌아갑니다.

설정 화면의 로그아웃 버튼은 중앙 확인창을 거쳐 실제 로그아웃합니다. 첫 내 정보 카드의 연필 버튼과 평가 주기 변경 버튼은 각각 준비 중 안내 모달을 엽니다. 내 요금제 Basic 표시는 시연용 목업이며 서버의 요금제 정보와 연결되지 않습니다.

홈의 음성 입력은 마이크 버튼을 누르면 빨간 중지 버튼으로 전환하고, 브라우저 음성 인식과 실제 마이크 진폭으로 파형을 표시합니다. 키보드·음성 전환에는 짧은 애니메이션을 적용하며 입력 버튼은 "구조화하기"입니다. 파형은 브라우저의 마이크 권한이 있어야 반응합니다.

리더보드의 "점수순"은 종합 점수 내림차순이고 "최근 상승"은 이전 평가 대비 점수 상승폭 내림차순입니다. 평가 설정에서 여러 ACTIVE 아이디어를 선택하면 동일한 가중치를 각 아이디어에 예약합니다. 일부 저장이 실패하면 실패한 항목만 다시 시도할 수 있습니다. 상세의 "이 아이디어 재평가"는 선택한 아이디어만 평가 요청하며 오늘 이미 평가한 경우 서버에서 E007을 반환합니다. 가중치 예약만으로 당일 제한이 해제되지는 않습니다.

카드 요약에는 첫 기록 시각을 보여줍니다. 근거 문서에는 `evaluatedAt`을 "평가에 반영"된 시각으로 표시합니다. 문서별 실제 수집 시각은 현재 평가 응답에 없습니다.

홈 탭은 아이디어 기록 화면입니다. 키보드·음성 입력에서 구조화 확인으로 바로 이어지고, 리더보드는 순위 목록, 내 아이디어는 회전 캐러셀로 보여 줍니다. 설정 탭은 회원 닉네임·이메일, 24시간 재평가 주기, 요금제 영역과 회원정보 영역을 카드로 표시합니다. 평가 주기 변경·요금제 조회·회원정보 수정은 백엔드 API가 없어 준비 중으로 안내하며, 로그아웃은 실제로 동작합니다.

평가 설정 선택 시트는 내용에 맞춰 높이가 줄어들고 아이디어가 많으면 목록만 스크롤합니다. 아이디어 카드의 점수는 고정된 오른쪽 영역에 두며 긴 제목은 줄바꿈합니다. 보류 아이디어에는 작성 시각과 저장된 구조화 내용을 표시합니다. 입력 원문은 현재 백엔드에 저장되지 않아 다시 표시할 수 없습니다.

리더보드의 아이디어 목록은 기본 스크롤바를 숨긴 세로 카드 캐러셀과 우측 점 내비게이션을 사용합니다. 필터와 카드, 새 아이디어 버튼은 hover·키보드 포커스 효과를 표시하며, 점수 이력 그래프는 선 아래 영역을 채웁니다. 평가 설정의 아이디어 선택은 점수 배지와 제목을 담은 카드로 표시하며 카드 목록만 내부에서 스크롤합니다. 자동 확인 카드의 수동 동작은 "지금 재평가"로 표기하고 24시간마다 근거 자료 변화 수집 및 재평가를 안내합니다.

아이디어 구조화 확인 화면은 원문을 "내가 적은 아이디어 원문"으로 표시하고, "이렇게 이해했어요" 제목과 안내 문구는 생략합니다. 네 항목의 연필은 카드 우측 상단에 두고 본문은 카드의 남은 너비를 사용하며, 입력칸의 크기 조절 손잡이는 숨깁니다.

CUE 로고가 있는 모든 화면은 카드 상단 여백을 동일하게 적용합니다(기본 30px, 낮은 화면 24px). 데스크톱의 카드 시작 위치도 화면 사이에 맞추고, 뒤로가기 버튼과 CUE 로고 사이 간격을 좁혔습니다.

카드 요약은 가운데 고정 크기이며 구조화 항목만 내부에서 스크롤합니다. 모든 스크롤 영역에 얇은 보라색 표시를 적용합니다. 상세 카드 안쪽 상단 여백을 줄이고, 최고 가중치 문구 없이 주황색 가중치·총점 기여를 보여주며 이전 평가 점수는 오른쪽에 배치합니다.

상세 화면의 구조화 수정·평가 설정·카드 요약 버튼은 가운데 정렬과 hover 효과를 적용합니다. 구조화 수정의 입력칸은 바깥 필드 카드 안에서 한 겹으로 표시합니다. 큰 화면 상세 카드의 상단 여백을 줄이고, 이전 평가 점수는 총점 아래 줄에 표시합니다. 총점 기여 막대는 주황색입니다.

평가 지표의 보라색 막대는 원점수, 주황색 막대는 현재 가중치를 반영한 총점 기여입니다. 가중치는 원점수 왼쪽에 표시합니다. 근거 카드의 보라색 바깥 그림자, 얇은 보라색 스크롤 표시, 큰 화면의 리더보드 상단 여백 축소를 적용했습니다.

03 상세 화면: 평가 결과에서는 평가 지표를 먼저 보여주고, 평가이유는 3줄로 접은 뒤 오른쪽 "더보기"로 펼칩니다. 근거 자료의 점수는 왼쪽 정렬, 문서 보기 문구는 오른쪽 정렬하며 이력은 `yy.MM.dd HH:mm` 형식입니다. 가중치 설정은 슬라이더와 퍼센트 양옆의 1% 감소·증가 버튼을 제공하며 합계가 100%일 때 저장할 수 있습니다. 공통 날짜는 `yy.MM.dd`로 표시합니다.

평가 지표의 보라색 막대는 원점수를, 그 아래 얇은 연보라 막대는 전체 100점 중 실제 총점 기여를 표시합니다(`원점수 × 현재 가중치 / 100`). 카드 요약에는 타깃·문제·해결·기대효과가 나옵니다. 근거 문서 카드는 호버·키보드 포커스·터치 시 은은하게 빛나고, 상세 탭은 활성화하면 보라색 밑줄이 표시됩니다.

스타일은 Tailwind CSS v4와 `@tailwindcss/vite`를 사용합니다. 공통 디자인은 `src/tailwindStyles.ts`의 유틸리티 매핑과 `tw()`로 구성하며 `src/styles.css`에는 Tailwind import, 전역 폰트·포커스·키프레임만 둡니다. 새 화면은 JSX의 Tailwind 유틸리티를 사용합니다. `npm install`, `npm run format:check`, `npm run build`로 확인하세요.

## 화면과 코드 구조

`src/pages/`는 시작·인증·입력·구조화 확인·리더보드·저장 결과·평가 상세를, `src/components/`는 공통 UI와 가중치·수정·근거 문서·변화 알림·카드 요약 모달을, `src/api/`는 요청과 응답 타입을 담당한다. Vite 개발 서버의 `/api` 프록시가 로컬 백엔드(8080)로 전달한다. 평가 중에는 상세를 폴링하고, 실패하면 오류 코드를 표시한다. 음성 입력은 브라우저 받아쓰기를 사용한다.

## CORS 브라우저 확인 페이지

이전 CORS 점검용 임시 페이지는 `cors-check.html`입니다. Python 3으로 저장소 루트에서 각각 별도 터미널을 열어 실행합니다.

```powershell
python -m http.server 5174 --bind localhost --directory frontend
```

백엔드가 `http://localhost:8080`에서 실행 중인지 확인하고, Chrome에서 `http://localhost:5174/cors-check.html`을 열어 **CORS 확인 실행**을 누릅니다. 기본 CORS 설정에서는 5174에서 브라우저가 응답 읽기를 차단해야 합니다. 5174의 실패가 네트워크 오류인지 CORS 오류인지 Chrome 개발자 도구 콘솔에서도 확인하세요. 이 페이지는 실제 프론트엔드 앱이 아니며 로그인 정보나 토큰을 사용하지 않습니다.

## React 앱 (로그인 · 입력)

`npm install` 후 `npm run dev`로 http://localhost:5173 에서 실행합니다. `npm run build`로 타입 검사와 번들을 확인합니다. IntelliJ에서 백엔드를 직접 실행할 경우 먼저 루트에서 `docker compose up -d db`를 실행하세요. API는 Vite의 `/api` 프록시를 거쳐 localhost:8080으로 전달됩니다.

회원가입은 `POST /api/users` 후 자동 로그인합니다. 로그인 토큰은 현재 탭의 sessionStorage에 보관하고, `A004` 만료 시 refresh 토큰을 교체합니다. 키보드·음성 입력은 브라우저에만 남으며, 음성 모드는 지원 브라우저의 SpeechRecognition을 사용합니다. 마이크 권한과 브라우저 지원이 필요합니다. 백엔드에 원문 자동 구조화 엔드포인트가 없어서 사용자가 네 항목을 직접 확인·작성한 후 `POST /api/ideas`로 저장합니다. 항목이 비면 HOLD로 저장되며 ACTIVE는 비동기 평가 상태를 표시합니다.

이전 CORS 점검용 HTML은 `cors-check.html`에 보관했습니다.

평가 상태 표시는 `evaluationStatus`와 `lastEvaluatedAt`을 함께 사용합니다. `IDLE`만으로 평가 완료라고 판단하지 않으며, 미평가/실패 상태에서는 `POST /api/ideas/{id}/evaluate`를 요청할 수 있습니다. Gemini 키가 없으면 백엔드가 `E001`을 반환합니다.
